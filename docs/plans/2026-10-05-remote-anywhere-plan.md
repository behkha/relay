# Remote anywhere: implementation plan

Spec: [docs/specs/2026-10-05-remote-anywhere-design.md](../specs/2026-10-05-remote-anywhere-design.md)
Branch: `remote-anywhere`

Open questions resolved with the spec defaults: when 443 is taken, fall back to 8443 (no user-chosen port); the LAN door stays token-only.

Rules for every task:

- `swift build -c release --arch arm64` passes after each task, and `scripts/selftest.sh` passes once it exists.
- No new package dependencies. System frameworks and the `tailscale` / `tmux` CLIs only.
- Match surrounding code style (comment density, naming, `Proc.run`, `Shell.quote`, `AppleScript.run`).
- One commit per task on `remote-anywhere`, plain message, no attribution trailers. Do not push.
- `--self-test` must run and exit before any listener, hook install or UI starts, so it never collides with a running Relay.
- Do not run `scripts/build.sh --install` and do not launch the real app.
- Tick the task's box in this file when it is done and committed.

## Tasks

- [x] 1. **Self-test harness.** In `RelayMain.main()`, if `CommandLine.arguments` contains `--self-test`, run `SelfTest.runAll()` and `exit(0/1)` before `NSApplication` is touched. New `SelfTest.swift` with a tiny `check(_:_:)` registry printing `PASS/FAIL name`. New `scripts/selftest.sh`: debug `swift build`, run the binary with `--self-test`, exit with its status. Seed with one trivial check.
- [x] 2. **Extract `RemoteAPI`.** Move the route handling, `snapshot()`, `answer()` and `transcriptJSON` from `RemoteServer` into `RemoteAPI.swift`. `RemoteAPI.handle(req, ex, caps:, device:)` where `caps` is a `Set<Capability>` (`read`, `answer`, `control`). `snapshot()` adds `caps` plus per-session heat (CPU % and level from `HeatMonitor`). `RemoteServer` (LAN) keeps token auth and passes `[.read, .answer]`. LAN behaviour must be byte-for-byte the same apart from the new fields.
- [x] 3. **`Devices.swift`.** `DeviceStore` (persisted to `~/Library/Application Support/Relay/devices.json`, 0600, atomic writes): devices `{id, name, publicKey (raw x963 base64url), ownerLogin, pairedAt, lastSeen, revoked, pushSubscription?, pushPrefs {blocked, finished, fire, hideContent}}`. Pairing codes: 32 random bytes, single use, 5 min expiry, in memory. `verify(request) -> Device?` implementing spec checks 1–5 (device, ±60 s, ECDSA P-256 SHA-256 over `method\npath?query\nts\nhex(sha256(body))` using `P256.Signing.ECDSASignature(rawRepresentation:)`, 120 s replay cache, `Tailscale-User-Login == ownerLogin`). Failure counter: >20 failures/minute triggers 60 s cool-down. Self-tests: valid sig, tampered body, stale ts (±61 s), replay, missing/wrong login, revoked device, expired and reused pairing code. Generate the signature fixture in-test with CryptoKit using raw r‖s, and add one hard-coded WebCrypto-format vector.
- [x] 4. **`Tailscale.swift`.** CLI discovery (`Proc.which("tailscale")`, else `/Applications/Tailscale.app/Contents/MacOS/Tailscale`). `status()` parses `tailscale status --json` (BackendState, MagicDNS suffix, `Self.DNSName` without trailing dot). `serveStatus()` parses `tailscale serve status --json` and reports which HTTPS ports are taken and whether they proxy to `127.0.0.1:47902`. `enable()` picks 443, else 8443, never overwriting a foreign entry; runs `serve --bg --https=<port> http://127.0.0.1:47902`; maps the "HTTPS certificates disabled" failure to a friendly error with the admin console link. `disable()` removes only Relay's entry (`serve --https=<port> off`). Each step returns a typed error with a user-facing message. Self-tests on canned JSON: running/stopped, 443 free, 443 foreign, 443 already ours.
- [ ] 5. **Tailnet listener and pairing routes.** New `TailnetServer.swift`: `HTTPServer(label: "tailnet", localOnly: true)` on fixed port 47902; if the port is busy, surface an error, with no fallback (add a strict-port option to `HTTPServer.start` if needed). Unauthenticated routes: `GET /`, `GET /pair`, the PWA assets (task 9) and `POST /api/pair`. Everything else goes through `DeviceStore.verify`, then `RemoteAPI.handle(caps: [.read, .answer, .control])`, then updates `lastSeen`. `POST /api/pair {code, publicKey, deviceName}` validates the code, then shows an `NSAlert` on the main thread ("Pair '<name>' (<login> via Tailscale)?"). Allow stores the device and returns `{deviceId}`; Deny returns 403. `ownerLogin` is fixed by the first pairing, and later pairings must match it. Wire on/off through a `RemoteAccess` controller holding `Tailscale` + `TailnetServer`, with state persisted in `UserDefaults` (`tailnetEnabled`).
- [ ] 6. **`WebPush.swift`.** VAPID key in `vapid.json` (0600). `vapidJWT(audience:)` (ES256, `aud` = endpoint origin, `exp` = now + 12 h, `sub` = `mailto:relay@localhost`). `encrypt(payload:, p256dh:, auth:)` per RFC 8291 / RFC 8188 `aes128gcm`, single record, 4096-byte record size. Endpoint allowlist: host is `push.apple.com` or ends in `.push.apple.com`, or equals `fcm.googleapis.com` or `updates.push.services.mozilla.com`; https only. `send(to device, payload, urgency, topic)` with the error table from the spec (404/410 drops the subscription, 413 resends hidden, 429/5xx retries at 2/10/60 s, offline queue of 20 per device flushed by `NWPathMonitor`). Self-tests: the RFC 8291 section 5 example decrypts and encrypts to the published ciphertext (inject the fixed salt and sender key), JWT header and claims decode and verify, and the allowlist rejects `push.apple.com.evil.test`, `http://` and `evilpush.apple.com`.
- [ ] 7. **Push triggers.** `PushDispatcher` called next to `Notifier.notify` in `Store.swift` (~line 494). Idle means `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType: .null)` ≥ 60 s, or the screen is locked (`CGSessionCopyCurrentDictionary` `CGSSessionScreenIsLocked`); then send now. Otherwise schedule for 45 s and cancel if the item is gone. Filter by each device's `pushPrefs`. Payload `{title, body ≤120, itemId, sessionId, kind}`, with the hidden body when `hideContent` is on. Topic is `base64url(sha256(itemId))` truncated to 32 chars. Heat fire transition sends at most one push per agent per 10 min. No-op when `Demo.isOn`. Routes: `POST /api/push/subscribe {endpoint, keys}`, `POST /api/push/prefs`, `POST /api/push/test`.
- [ ] 8. **Remote start and kill.** `Launcher.newDetachedTmux(workspace:, folder:, prompt:, mode:) -> launchId`, using `tmux new-session -d -s relay-<id> -c <folder> '<envPrefix> RELAY_LAUNCH_ID=<id> claude [--permission-mode plan|acceptEdits] <quoted prompt>'`. Errors if tmux is missing. Known folders: distinct working directories of sessions per workspace (from `Store` plus whatever history Relay already reads), plus pinned folders in `UserDefaults` (`pinnedFolders`). Reject anything else. `relay-hook.sh` adds `-H "X-Relay-Launch: ${RELAY_LAUNCH_ID:-}"` in both header lists. `Store` keeps `pendingLaunches` (placeholder rows exposed in `snapshot()`), claims them on `SessionStart` with a matching launch header, and after 30 s turns them into an error row with the last `tmux capture-pane -p -t relay-<id>` lines. Routes (control cap): `GET /api/folders`, `POST /api/start`, `POST /api/kill {sessionId}` (same path as the Mac's Kill agent), `GET /api/terminal?id=` (last 60 lines of `capture-pane` for tmux agents). Mac toast on remote start and kill. Self-tests: start rejects an unknown folder and `bypassPermissions`, and the prompt is quoted (a prompt containing `'; rm -rf ~` round-trips as one argument).
- [ ] 9. **Phone UI and PWA.** `remote.html`:
  - `api()` signs requests when a device key exists in IndexedDB (WebCrypto ECDSA P-256, non-extractable), else uses `?t=`.
  - `/pair` flow: read the code from the fragment, generate the key, POST, wait for the Mac's approval.
  - The first-run three-step guide.
  - Tabs: Inbox, Agents (heat badge, last activity, Kill with confirm and 2 s undo), and the `+` New agent sheet (workspace, folder, prompt, mode, Start, "Starting…" row).
  - Session sheet Terminal toggle.
  - Device sheet: name, notification status, Enable notifications button, test push, per-event toggles, hide content, Forget.
  - Polling paused when hidden, unreachable banner with the last-updated time, and `getNotifications()` cleanup on open and poll.
  - Deep links `#item=` and `#session=`.

  New resources `manifest.webmanifest` and `sw.js` (push: `showNotification` with `data`, `tag` = itemId; notificationclick focuses or opens `/#item=<id>`). PNG icons at 192 and 512 generated in `build.sh` from the iconset. Add every new resource to the `cp` line in `build.sh`. The UI is gated by `caps`.
